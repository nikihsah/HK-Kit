# Project Journal

Project Journal records project evolution.

It is separate from Candidate Registry.

## Stores

- current strengths
- unresolved weaknesses
- player answers
- priority shifts
- open questions
- resolved conflicts

## Does Not Store

- full candidate lists
- full rule text
- long reasoning chains
- duplicate Candidate Registry data

## Format

```json
{
  "current_strengths": [],
  "unresolved_weaknesses": [],
  "player_answers": [],
  "priority_shifts": [],
  "open_questions": [],
  "resolved_conflicts": []
}
```

Keep it compact.
